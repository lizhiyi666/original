# PCDG-Geo：10%统计容忍度修订

本轮仅将 DailyLoc/G-RANK 的 JSD 相对同城 Full 的退化上限由5%改为10%。这是查看训练侧确认结果后的探索性验收规则修订，不是原5%协议的成功，也不是未接触过测试基准的独立泛化验证。旧 `pcdg-geo-v1-20261010` 保持 `stopped`，全部文件、原始身份和指纹保留。

## 接口与继承

`tools/run_geometry_study.py` 增加 `--other-jsd-relative-tolerance`（默认0.05），以及必须成对指定的 `--inherit-geometry-run`、`--inherit-geometry-inventory`。本轮用独立目录及 run ID `pcdg-geo-v1-tol10-20261010`，显式指定0.10；启动入口为 `tools/launch-pcdg-geo-tol10.sh`。

继承前核对旧交付清单、全部来源文件和原部署源码哈希；科学代码除换行外逐字节一致，修改过的控制器内采样、候选、几何和正式细化函数另作 AST 一致性检查。模型、数据、划分、种子、步数、预算、精度、设备及参考指纹必须相同。旧源码和来源运行不能与新部署重叠。

原终态产物逐字节复制到新输出的 `inherited/geometry-v1/`，payload/receipt 保留旧 manifest 身份；新 manifest 记录原清单哈希与引用关系。原确认结果仅作历史记录，不能混入新筛选。恢复要求新 manifest 完全一致，缺失继承缓存或哈希不符直接停止，不重新采样、不覆盖冲突文件。

## 固定流程

1. 复用64个训练侧基础批次（筛选16、确认48）和12组×2城的筛选候选，不重跑 Full/JointGen 或时间生成。
2. 使用10%门槛重排原12组；预期4组合格，前三为 `r1-b0.1`、`r2-b0.1`、`r4-b0.1`。算法按真实数值排序，不硬编码这三个名字。
3. 新前三组在两城市、135398/135399/135400三种子上确认，共18项训练侧细化。原 `r0.5-b0.1` 第四名不补位。
4. 继承初始50/100/200步资格证据，固定200步。仅通过新质量门槛、且 Distance/Radius 不差于 Full 的候选，依次进行新的配置专属在线速度复验；2城×普通/最长64条，2次预热、5次计时，中位完整空间采样增时≤10%。计时包含新评分与全部末端处理，不把缓存处理耗时当在线速度。
5. 首个同时合格者冻结配置，再细化旧6份正式 Full，产生 Full/Distance-only/Radius-only共18份正式结果；不根据测试结果追加配置。确认或速度全部失败即停止。

仍保持 FP32、TF32关闭、batch64、原基础投影预算、80%显存上限及独立随机流。实际类别序列、条件、时间、长度、类别/偏序指标和 Distance 端点集合须保持不变。几何目标读取原封存未舍入结果；不保证达标。
