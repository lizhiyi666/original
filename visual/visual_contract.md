# 方法图视觉契约

## 使用边界

本契约只抽取 `Marionette.png` 的视觉组织原则，不复制其科研内容、文字、图标、变量、模块名称或具体版式。目标是形成一张更紧凑、更规范、适合硕士论文排版的 POI 偏序约束扩散方法图。

## 1. Overall layout：分层但不堆叠

- 采用少量大型圆角容器组织方法阶段，容器代表“语义层/计算层”，而不是每个函数一个框。
- 视觉上先建立全局区域，再在区域内部放置少量关键模块；避免把完整代码调用链平铺成流水账。
- 论文图建议使用“主流程 + 局部放大”的紧凑构图：主图呈现数据、生成基础、偏序约束介入、输出；细节图解释一个 reverse step。
- 借鉴其分区清晰的优点，但不要直接复用“三条横向大带”的具体结构。可改用左到右主流程，右侧或下方嵌入 reverse-step inset，形成自己的信息架构。

## 2. Panel organization：面板承担不同叙事任务

建议设置三个语义面板：

1. **Input & representation**：展示时间、category、POI、条件、偏序矩阵的统一表示。
2. **Joint diffusion generation**：展示时间 Add-Thin 与 category/POI 离散扩散的并行或耦合关系。
3. **Partial-order constrained reverse step**：放大一个反向采样步，突出“预测 logits → category 投影 → category/POI 联合采样”。

面板之间应有明确的阅读顺序；面板内部只保留解释该层所必需的对象。评价指标、基线方法和训练期辅助损失宜放入独立实验图，不挤占主方法面板。

## 3. Main data-flow direction：一条主方向，局部允许逆向时间轴

- 整张论文图应有一条主阅读方向，推荐从左向右：输入 → 表示 → 条件生成 → 约束反向采样 → POI 序列输出。
- reverse diffusion 的时间步可以在局部 inset 中用右到左箭头表达，但必须标注“局部采样时间轴”，避免读者误解整张图的主流程方向。
- 条件信息使用从上方或侧方汇入主模型的短连接线；不要让条件线跨越整张图形成难以追踪的长曲线。
- 任何回路只用于表达迭代/重复采样，不用于装饰。

## 4. Module hierarchy：三层框层级

采用三级视觉层级：

- **Level 1：阶段容器**：数据、联合扩散、约束采样、输出；使用浅色背景和较粗边界。
- **Level 2：核心模块**：条件编码器、Add-Thin 时间模型、离散 Diffusion Transformer、偏序能量/投影器；使用实色填充和中等圆角。
- **Level 3：机制细节**：`po_matrix → constraint set → violation energy → KL-ALM projection`、mask、Gumbel-softmax、采样等；使用小型白底框或简短注释。

不要让 Level 3 的函数名与 Level 2 的模型框具有相同视觉权重。函数名可作为小号灰色注释放在模块底部。

## 5. Contribution highlighting：只突出一个主创新

- 现有基础模块用低饱和蓝/灰/绿表示，边界稳定、填充克制。
- 论文创新“类别偏序约束”使用唯一的强调色（建议橙红或深紫），并配合更粗边框、浅色强调底和一条醒目的约束箭头。
- 主创新应在视觉上形成连续链条：

  ```text
  sample-level po_matrix
  → differentiable order/existence energy
  → category-logit KL-ALM projection
  → joint category/POI sampling
  ```

- 不要同时用多种高饱和色突出 `PartialOrderLoss`、CFG、PostSwap、EnergyGuide；这些属于训练探索项或对照基线，主图中应弱化或移出。
- “只作用于 category logits”必须成为创新框旁的短标签，而不是藏在图例里。

## 6. Arrow style：箭头编码语义，不做装饰

- **实线粗箭头**：主数据流或张量流。
- **细实线箭头**：普通条件输入、元数据或辅助连接。
- **短虚线箭头**：扩散迭代/反向时间步，旁边标出步数方向。
- **强调色箭头**：偏序约束介入路径，只使用一条主色通道贯穿矩阵、能量、投影器和 category logits。
- 箭头应尽量直角转折或使用短圆角折线；避免跨越多个面板的长弧线。
- 箭头终点应落在具体模块边界或 token 分布上，禁止悬空。
- 采样前的投影位置要用一个清晰的“插入点”标出：`model logits` 和 `joint sampling` 之间。

## 7. Box hierarchy：容器、模型、机制三种框形

- 阶段容器：浅色填充、细灰边或低对比边界、较大圆角。
- 核心模型：中等圆角、实色填充、深色文字；模型名称置中，必要时附一行输入/输出说明。
- 约束机制：可用虚线外框包住“能量 + 投影”子模块，表示它是插入生成器的控制层，而不是另一个生成器。
- token 序列或概率分布：使用窄条、网格或小矩阵表达，不要使用大面积装饰性卡片。
- 同一层级的框应保持相近宽度、圆角半径和边框粗细；避免一个小函数框比主模型更醒目。

## 8. Typography hierarchy：论文排版优先

- 阶段标题：黑体/无衬线粗体，约 9–12 pt（按最终版面缩放）；只写阶段语义，不写长句。
- 核心模块名：8–10 pt，中等粗细；英文模型名可保留，中文说明另起一行。
- 机制注释：6.5–8 pt，深灰色；公式只保留一条核心能量或投影表达。
- token、变量和时间步使用统一数学字体；不要在同一图中混用多种公式字体。
- 颜色不能承担唯一语义；所有关键颜色都要配文字标签或线型差异，以适应黑白打印。
- 标题、模块名、注释的字号差至少一个层级；避免全图所有文字都用同样大小。

## 9. Spacing：紧凑但可呼吸

- 阶段容器之间保持稳定的外间距；核心模块之间的间距小于容器间距，体现层级关系。
- 每个模块内部保留足够内边距，文字不要贴边；框内最多两行主标题加一行短注释。
- 连接线周围留出空白，避免穿过文字或 token 图形。
- 主图优先控制在单栏宽度可读；若必须双栏，所有模块按同一基线对齐。
- 对论文版面建议使用 8 pt 左右的最小可读注释字号，并在导出 PDF 后以 100% 比例检查。

## 10. Use of color：低饱和底色 + 单一创新色

建议采用可打印、色盲友好的低饱和配色：

- 基础生成模块：浅蓝/蓝灰；
- 时间分支：浅青或冷灰；
- 离散 category/POI 分支：浅绿或浅蓝绿；
- 偏序创新链：橙红或紫红强调色；
- 特殊 token、padding、mask：白/浅灰，并用纹理或边框区分。

控制规则：

- 全图主色不超过 4 种，强调色只保留 1 种；
- 背景颜色只用于区分阶段，不用于标记每个数据类型；
- category token 与 POI token 可以用两种相近色，但必须附图例；
- 颜色透明度和边框对比度要保证打印后仍能辨认。

## 11. Overview/detail relationship：主图讲“是什么”，细节图讲“怎么做”

主图只回答四件事：

1. 输入是什么；
2. 时间与 category/POI 如何联合生成；
3. 类别偏序约束在哪里介入；
4. 最终如何得到 POI 序列。

细节图再展开：

- 离散 q/p 转移和 x0 参数化；
- `W_A/W_B` 编译；
- 顺序违规与存在性违规的计算；
- KL、增广拉格朗日、Gumbel-softmax 迭代；
- `category_mask`/`poi_mask` 的 token 位置布局；
- `Batch.to_seq_list` 的 GPS 反序列化。

主图与细节图之间使用编号或 callout（如 “① 偏序投影细节”），不要在主图重复完整公式。主图中的创新框应能独立理解，即使读者不查看细节图。

## 12. 针对本课题的推荐构图

为避免复制参考图的三段式外观，推荐如下独立构图：

```text
[Input / POI event representation]
                →
[Conditional joint generator]
  ┌─────────────┴─────────────┐
  │ time Add-Thin             │
  │ category/POI discrete DD  │
  └─────────────┬─────────────┘
                →
[Reverse-step inset]
  model logits → PO matrix energy → category-only projection → joint sampling
                →
[Generated POI sequence + evaluation]
```

其中偏序矩阵从输入表示或约束侧边输入到 reverse-step inset；不要把它画成 denoiser 的普通条件 embedding。若后续真的把 `po_encoding` 注入 `ConditionEmbeddingModel`，再单独更新视觉契约和方法图。

## 13. 论文级质量检查清单

- 缩小到论文单栏宽度后，主创新链仍能一眼识别；
- 只存在一条明确的主数据流；
- category-only 投影位置清晰且没有误导为 POI 过滤；
- 所有高层框都对应实际代码阶段；
- 未实现的 CFG、复杂 DAG 自适应、candidate filtering 不出现在主方法图；
- 主图不出现调试参数、GPU 分块、日志和 checkpoint 细节；
- 黑白打印、灰度打印和色盲模式下仍能区分主模块；
- 公式、变量、箭头和图例的字号达到论文 PDF 的可读标准；
- 参考图只提供视觉组织启发，不复制其具体内容、图标、标题、箭头路径或面板排列。
